# Upload service

## Summary

A group of services for handling media uploads and transformations.
A Cloudinary clone.

Main conceptual differences compared to Cloudinary:

- There are only named transformations, the client cannot set custom transformation parameters.
- The upload response does not contain anything. The webhook transfers the file metadata instead.
- Progress tracking webhook for async eager transformations.
- All uploads must be signed.

## Definitions

- Upload: A file uploaded to the service. It has a unique upload key.
- Transformation: A process that takes an upload and outputs one or more derivatives.
- Derivative: The output of a transformation. Can consist of multiple files.
- Named transformation: Transformation parameters registered with a unique name.
- Eager transformation: A transformation that is applied after upload.
- Incoming transformation: A transformation that overwrites the original upload when completed.
- Async transformation: The eager+incoming transformations can be blocking or async (queued).
- Signature: An encrypted signature generated by the admin server that indicates if the paired upload/read parameters
  changed.
- Upload request: A file upload with a defined upload key, signature, and optional eager+incoming transformations or
  other parameters.
- Upload preset: A pre-defined upload request parameters. Any parameter can be overridden.
- Read: The uploads and their derivatives can be read from the client.
- On-demand transformation: A transformation that is executed during read and then cached.
- Authorization: Some uploads are private. They require a signature to be read.
- Completion webhook: A URL that is called after the upload and it's transformations are completed if provided.
- Progress webhook: Webhook for async transformation progress tracking.
- Media metadata: Video or image specific metadata (e.g., resolution) that is sent to the completion webhook.
