# Multi region replication plan
## Replication
The data is replicated between the CockroachDB and Minio regions.
The Minio regions are using the slower asynchronous replication.
If an upload exists in the database of a region, but the files are not in the local object storage, then
they are read from the home region then cached.
The home region is stored in the database.

## The update problem
If an upload is re-created, or a variant is regenerated by a different transformation version, the change must be
indicated in the database.
If the file read would only check for the existence of a file, then could read the older file before the object storage
is synchronized without knowing it, so it wouldn't attempt to fall back to the home region.
(Example approach: appending the asset version to the object key prefix)

## The directory variant replication problem
Some variants are directories, they consist of multiple files, for example, a HSL video.
It's possible that the playlist is asynchronously synchronized to another region before all segments arrive.
This could cause a long fallback in the middle of the video.
The directory variant does not save the list of all files, so we cannot know when a requested file is supposed to exist or not.
As a result, all reads of non-existent file would attempt to read the home region.
This could be exploited to stress the server.
This might be an insignificant edge case if the inter-region fallback is not too long and the
abuse can be stopped by the gateway.

## The directory variant update replication problem
When a directory variant is updated, it must make sure to avoid reading the older files in all regions.
This should be fixed by the same version check mechanism that the read must use in general.
